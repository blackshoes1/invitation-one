## Production deployment safety

- Production is Vercel project `invitation-one` in scope `geunyoungs-projects-0d71c3ce`, serving `https://kkachi.vercel.app`.
- Deploy the latest GitHub `blackshoes1/invitation-one` `main` commit through the Git integration. Check remote `main` immediately before releasing and compare the live deployment's Git SHA afterwards.
- Never redeploy a historical deployment to refresh production. Vercel Redeploy keeps that deployment's old commit even when `main` has advanced.
- Do not use Promote, Instant Rollback, direct alias changes, or `--prebuilt` for routine production releases; they can bypass the remote build guard. An intentional rollback requires the user's explicit rollback instruction for that version.
- Keep the project-level Build Command generated by `node scripts/deploy/production-guard.mjs --project-settings`. Do not override it with `vercel.json` or deployment-specific settings. It protects historical source snapshots as well as current code.
- Run `node --test scripts/deploy/production-guard.test.mjs` after changing release safeguards. See `docs/DEPLOYMENT_SAFETY.md` for setup and verification limits.
