# 개인 초대 링크의 우리 모임 공간 개발 프롬프트

## 목표
그룹 소속 개인이 기존 개인 초대 링크로 진입하면 개인 인사와 청첩장 바로 보기를 제공하고, 선택적으로 우리 모임 공간을 열 수 있게 한다. 그룹 소속·청첩장 전달 신청·결혼식 참석은 별개다. 개인 링크의 주문 종류를 그룹 주문으로 바꾸지 않는다.

## 구현 계약
- 기존 128bit 개인 초대 토큰으로 서버에서 명단 구성원과 소속 그룹을 확인한다. 일반 그룹 slug만으로 명단/참석 정보에 접근할 수 없다. 그룹 없는 초대에는 공간을 노출하지 않는다.
- 첫 카드: 개인 이름과 그룹 이름으로 인사, `모바일 청첩장 보기`를 주 버튼, `우리 모임 보기`를 보조 버튼으로 제공한다. 배달 마감 여부와 무관하게 표시한다.
- 내 참석 응답: 참석 / 미정 / 불참 / 응답 지우기. 언제든 변경 가능하고 기본값은 응답 전이다. 관리자 일괄 주문이나 기존 마음배송 정보를 참석 응답으로 자동 변환하지 않는다.
- 기본 공개 범위는 본인+관리자. 공유 동의는 기본 해제다. 동의하면 모임에 내 이름과 참석 여부를 표시하고, 철회하면 다음 조회부터 숨긴다.
- 다른 구성원의 이름은 기본 마스킹. 공유하지 않은 참석 여부와 불참/미정/미응답 합계는 응답 payload에도 담지 않는다. 공개 요약은 공유에 동의한 참석 예정자 수만 제공한다. 명단 인원은 group_members만 센다.
- 전화번호, 주소, 내부 명단 ID, 토큰 hash는 그룹 응답에 포함하지 않는다. 그룹 전달 일정은 취소·숨김을 제외한 날짜/시간만 보여주고, 참석 응답과 별개임을 명시한다. 개인 배송지는 공개하지 않는다.
- 참석 정보는 별도 RLS 테이블에 보관하며 anon/authenticated 직접 권한을 회수한다. 서버만 접근한다. API는 매 요청 토큰을 확인하고 IP 요청 제한 및 no-store를 적용한다. 저장 대상의 member/group ID는 클라이언트 입력을 신뢰하지 않는다.
- 관리자 그룹 명단에서 실명 옆에 결혼식 참석 상태와 공유 여부를 확인한다. 관리자가 공유 동의를 대신 켜는 기능은 넣지 않는다.
- 링크를 전달받은 사람은 해당 구성원 권한을 갖는 bearer-link 방식임을 안내한다. 1:1 전달을 권장한다.

## 데이터·검증·배포
- 기존 데이터/과거 migration을 수정하지 않고 새 migration만 추가한다. 기존 초대 링크를 재발급하지 않는다. 실제 하객 대상으로 테스트 응답·문자·알림을 생성하지 않는다.
- 테스트: 잘못된 토큰 거부, 그룹 없는 토큰 거부, 자기 응답만 저장, 응답 형식 검증, 기본 비공개, 동의/철회, 다른 그룹 미노출, 명단 수와 신청 수 분리, 마감 시 공간 접근, 기존 개인 주문 판정 유지.
- 단위/API 테스트, TypeScript, ESLint, build를 실행한다. 가능하면 격리 DB/브라우저도 검증한다. 실행 못 한 항목과 운영 적용 여부를 구분해 보고한다.
- 새 환경변수 없이 기존 개인 초대 토큰과 서버 Supabase 연결을 사용한다. migration 적용 후 앱을 배포한다.

## 비범위
채팅/댓글, 그룹원의 전화번호·개인 배송지 공유, 기존 참석 시스템 전체 통합, 앞선 보안 리뷰의 다른 문제를 함께 수정하는 작업은 포함하지 않는다.
