# 도트 마당 'AI 에셋(ChatGPT 이미지) 도입' 설계

작성일: 2026-10-07 · 상태: 사용자 결정(경로 A: 사용자가 ChatGPT 로 시트를 뽑고, 변환은 우리가 한다) → 사용자 승인 → 구현 완료(배경 교체는 사용자 제공 이미지 대기)
선행 문서: `2026-10-07-guestbook-village-crowd-design.md`(꽃길·보통 체형·북적임), `…hd-design.md`, `…garden-design.md`, `…topdown-design.md`, `…pixel-village-design.md`

## 이 문서의 위치

사용자가 ChatGPT 이미지로 만든 캐릭터 시트(고해상도 도트 느낌의 치비, 음영·표정이 살아 있음)가 코드 생성 그림보다 훨씬 낫다.
그래서 **캐릭터는 AI 시트를 변환해서 쓰고**, 코드 생성 캐릭터 엔진(`figure.mjs`·`chargen.mjs`)은 쓰지 않는다.
세계 크기·이동 규칙·이름표·말풍선 같은 나머지 설계(crowd 설계)는 그대로 두고, 아래 항목만 이 문서가 대체한다.

| crowd 설계 항목 | 이 문서에서 |
|---|---|
| 캐릭터를 코드로 그림(`figure.mjs`), 32×64 프레임 | AI 시트를 잘라 붙인 **@2x 시트**, 논리 크기 **40×64**(시트 프레임 80×128) |
| 하객 96종 조합 생성 | 시트에 있는 사람 수만큼(약 30명), 하객은 `hashId(id) % GUEST_LOOKS` |
| 열: 앞·뒤·옆(오른쪽, 왼쪽은 반전) × 3프레임 = 9열 | 열: **앞·뒤·왼쪽·오른쪽 × 3프레임 = 12열**(왼쪽·오른쪽을 따로 그린 그대로 쓰고 반전하지 않는다) |
| 시트 PNG 500KB 이하, "PNG == 생성기" 테스트 | 시트는 WebP(무손실~근사 무손실), **1.2MB 이하**. 원본 시트는 저장소에 넣지 않으므로 "결과물 속성 테스트"로 검증 |
| 배경을 코드로 그림(384×512) | **ChatGPT 배경 이미지**를 세로(3:4)로 다듬은 @2x 이미지(논리 384×512, 실제 768×1024). 배경이 올 때까지 지금 배경 유지 |

## 원본 에셋 (저장소 밖)

- 원본은 `village-src/` (git 제외)에 둔다. 현재 `public/pic/dot_img1~4.png` 에 있는 네 장은 `village-src/` 로 옮겨 쓴다(커밋하지 않는다).
- 원본 시트 형식(사용자 이미지): 1536×1024 RGBA 투명 PNG, 한 장에 **캐릭터 8명(4열×2행)**. 캐릭터 한 명 = **3열×4줄**: 1줄 앞, 2줄 왼쪽, 3줄 오른쪽, 4줄 뒤(줄마다 프레임 3개: 걷기1·가운데·걷기2 로 보이는 구도). 격자가 정확하지 않아 위치·크기가 조금씩 다르다. 알파는 몸통 약 252/255, 가장자리에 옅은 번짐이 있다.
- 신랑·신부(②)와 배경(③)은 사용자가 추후 같은 방식으로 뽑아 넣는다. 그 전까지 신랑·신부는 시트의 한 명씩으로 임시 대체한다(검은 정장 한 명, 흰 드레스 한 명을 하객 목록에서 빼서 쓴다).

## 변환 스크립트 (`scripts/village-art/ingest.mjs`, 저장소 안)

- 입력: `village-src/*.png`. 출력: `public/pic/village-sprites.webp`(+ 행 목록 메타). 외부 의존성 추가 없음(PNG 디코드는 기존 `png.mjs`, WebP 인코딩은 Next 가 이미 가진 `sharp` 를 개발용으로만 쓴다 — `package.json` 에 추가하지 않고 테스트는 `sharp` 를 import 하지 않는다).
- 처리: 시트에서 캐릭터 블록과 프레임을 **알파 연결 성분**으로 찾아 자른다 → 가장자리 옅은 번짐 제거 → 같은 시트·같은 줄 안에서 **같은 배율**로 맞춘다(머리 크기가 방향마다 같게) → 프레임 안에서 **발끝이 아래 중앙**에 오게 정렬 → 12열 시트로 쌓는다. 어떤 줄이 어떤 방향인지, 프레임 순서(걷기1·가운데·걷기2)는 눈으로 확인한다.
- 원본 그림에 방향이 잘못 그려진 줄·프레임이 있어, 변환 단계에서 일부 오른쪽 줄을 왼쪽 줄의 좌우 반전으로 대체하고(MIRROR_RIGHT) 특정 프레임을 덮어쓴다(FRAME_OVERRIDES). 시트 자체에는 왼쪽·오른쪽 열이 모두 있으므로 앱은 반전하지 않는다.
- 결과를 눈으로 검수하는 연락표(작업 폴더)를 만든다. 4방향이 같은 사람으로 보이고 크기·발 위치가 맞아야 한다.

## 시트 규격 (`public/pic/village-sprites.webp`)

- 배율 `SHEET_SCALE = 2`. 프레임 80×128(논리 40×64), 열 12개: `down_idle, down_walk1, down_walk2, up_*, left_*, right_*`, 줄 = 사람 1명(하객 N명 → 신랑 → 신부). 배경 투명.
- 걷기 사이클은 `walk1 → idle → walk2 → idle`(기존과 같다). 프레임 이름은 `${view}_${anim}`, view ∈ `down|up|left|right`.
- 발끝은 프레임 맨 아래 가까이, 몸은 가운데. 앱은 `(x, y)` 를 발 밑 중앙으로 쓴다.

## 앱 쪽 변경

- `pixelSprite.ts`: `SPRITE_W=40`, `SPRITE_H=64`(논리), `SHEET_SCALE=2`, 프레임 이름 12개, `GUEST_LOOKS`(시트의 하객 수), 신랑·신부 줄, `SHEET_SRC` = webp, `frameRect(row, frame)` 는 시트 픽셀 사각형.
- `villageSim.ts`: `spriteFor` 는 `{ frame }` 만 돌려준다(왼쪽·오른쪽을 따로 그리므로 `flip` 없음). `HALF_W=20`, `BOX_H=64` 로 맞춘다(논리).
- `PixelVillage.tsx`: 시트를 논리 크기로 그린다(`drawImage(sheet, sx, sy, sw, sh, dx, dy, sw/2, sh/2)`), 이미지 부드럽게 보간(`imageSmoothingEnabled = true`, 도트 배율 렌더가 아니라 @2x 그림이므로).

## 위험

- **캐릭터 사이 크기·화풍 차이**: 한 시트 안의 배율을 통일하고, 시트마다 머리 폭 기준 보정이 필요하면 연락표를 보고 정한다.
- **하객 수가 30명 안팎이라 id 충돌**로 같은 모습이 겹침: 의도된 한계. 더 필요하면 사용자가 시트를 더 뽑아 `village-src/` 에 넣고 `npm run village:ingest` 를 다시 돌린다.
- **시트가 큼**(약 960×4400): 용량 예산(1.2MB) 테스트. 초과하면 근사 무손실 품질을 조정한다.
- **저작권**: ChatGPT 이미지는 사용자의 생성물이다. 참고 영상의 그림은 쓰지 않는다.
