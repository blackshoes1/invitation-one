# 도트 마당 '꽃길 + 보통 체형 하객 + 북적임' 설계

작성일: 2026-10-07 · 상태: 사용자 승인 → 구현 완료(배경 교체는 사용자 제공 이미지 대기)

> 캐릭터 그림(코드 생성)과 배경(코드 생성) 부분은 2026-10-07-guestbook-village-ai-assets-design.md 가 대체했다(캐릭터는 AI 시트로, 배경은 사용자 제공 이미지가 오면 교체).

선행 문서: `2026-10-07-guestbook-village-hd-design.md`(2배 해상도), `…garden-design.md`(정원 예식장), `…topdown-design.md`, `…pixel-village-design.md`

## 이 문서의 위치

HD 마당의 그림이 아쉬워서, 사용자가 보여 준 참고 영상(인스타 카드 속 방명록 화면)에 가깝게 올린다. 영상 프레임은 세로로 긴 화면에 꽃이 핀 흙길이 있고,
머리가 작은 **보통 체형** 하객 수십 명이 음영·또렷한 외곽선·안경·모자·가방 같은 소품과 함께 길을 가득 메우고 걸으며,
이름표는 작은 글씨에 흰 테두리, 말풍선은 흰 둥근 상자에 꼬리와 이모지가 붙는 모양이다.

AI 그림 도구나 외부 에셋을 쓰지 않고, 저장소의 **코드 생성 파이프라인**(`scripts/village-art/`)을 끌어올려서 만든다(사용자 결정: "내가 도구 쓰는 게 아니라 네가 해라").
참고 영상의 그림·에셋은 다른 서비스 것이라 **그대로 가져오거나 베끼지 않는다.** 구도·밀도·분위기만 참고한다.

아래 항목만 HD 설계를 대체하고, 나머지(걷기 규칙, 신랑·신부 동작, 갤러리 이동, 자동 말풍선, 글씨 선명화, 터치·절전·접근성·에러 처리, 입장 방식)는 그대로 둔다.

| HD 설계 항목 | 이 문서에서 |
|---|---|
| 세계 384×352 가로 정원 | 세계 **384×512 세로 꽃길** (3:4, 참고 영상 비율) |
| 캐릭터 32×48 아기 체형(머리 ≈ 키의 1/3) | **32×64 보통 체형**(머리 ≈ 키의 1/4.5) |
| 하객 64종, 시트 `288×3168` | 하객 **96종**, 시트 **9열 × 98줄**(하객 96 + 신랑 + 신부), `288 × 6272` |
| 걷는 영역 `x∈[16,368]`, `y∈[144,352]` | `x∈[80,304]`, `y∈[168,512]` |
| 이름표는 겹쳐도 모두 그림 | 앞사람이 가린 뒷사람 이름표는 **숨김**(신랑·신부 이름표 우선) |
| 말풍선: 금색 테두리 직사각형 | 흰 **둥근 상자 + 꼬리 + 은은한 그림자**, 이모지 그대로 표시 |

## 목표 · 범위

- **포함**: 새 캐릭터 그림(보통 체형·음영·세밀한 얼굴·머리 8종·옷 6종·소품), 세로 꽃길 배경, 이에 맞춘 세계·캐릭터 상수와 신랑·신부 좌표, 이름표 겹침 숨김, 말풍선 모양,
  30~60명이 몰려도 도는지 확인하는 검증(스크린샷 비교 포함), 관련 테스트.
- **제외**: 외부 에셋·AI 도구 도입, 새 동작, 장애물·충돌, DB·API 변경, 새 npm 의존성.
- 한계(약속): AI·작가가 그린 그림만큼은 안 나온다. 목표는 참고 영상의 약 80%이며, 비교 이미지를 보고 사용자가 다음 단계를 정한다.

## 캐릭터 시트 (`public/pic/village-sprites.png`)

- 프레임 **32×64**, 열 9개는 그대로(`down_idle … side_walk2`, 왼쪽은 오른쪽 옆모습 반전). 줄 0~95 = 하객 96종, 줄 96 = 신랑, 줄 97 = 신부. 배경 투명.
- 발끝은 프레임 맨 아래 가까이(최대 1px 위)에 닿고 몸은 가운데에 선다. 앱은 `(x, y)`를 발 밑 중앙으로 쓴다.
- **미술 기준**(구현자는 참고 영상 프레임과 나란히 놓고 눈으로 확인하며 다듬는다):
  1. 어른 체형: 머리 높이 약 14~15px, 어깨 너비 약 12px, 다리 길이 약 25px. 걷기 3프레임은 팔·다리 흔들기에 1px 위아래 몸 흔들림을 더한다.
  2. 음영 3단(밝음·기본·어두움) + **색 외곽선**(채움색을 어둡게 한 색, 검정 아님). 바닥에 가벼운 발 그림자.
  3. 얼굴: 눈 2×2 + 하이라이트 1px, 눈썹, 코 그늘 1px, 입, 볼. 옆모습은 코·턱선이 보인다.
  4. 머리 8종(짧은·가르마·단발·긴·포니테일·올림·곱슬·스포츠) — 기본색 + 하이라이트 결 + 뒷머리 볼륨. 뒤에서 본 머리도 방향에 맞게.
  5. 옷 6종(티셔츠·셔츠+칼라·후드·원피스·가디건·재킷) — 주름 음영, 밑단·소매 구분. 하객에게 정장 세트는 없다(재킷은 캐주얼).
  6. 소품: 안경, 캡, 버킷햇, 머리 꽃, 리본, 목도리, 크로스백 끈. 조합은 시드 고정.
  7. 96종은 모두 서로 다른 조합이고 머리 모양·옷·피부색이 골고루 나온다(각 머리 모양 8종 이상, 각 옷 10종 이상).
  8. 신랑: 짧은 머리, 검은 정장·흰 셔츠·빨간 타이·가슴 꽃. 신부: 긴 머리에 머리 꽃(또는 베일), 흰 드레스, 부케. 두 사람은 하객보다 한눈에 구분되어야 한다.
- PNG 크기 예산: 시트 500KB 이하(테스트로 확인).

## 배경 (`public/pic/village-bg.png`)

- **384×512**, 모든 픽셀 불투명. 위쪽(약 y 24~150)에 꽃 아치 + 작은 단상, 가운데로 곧게 내려오는 **흙·자갈 길**(약 `x∈[120,264]`, 가장자리에 돌과 풀이 번짐),
  길 양옆은 여러 색(흰·분홍·보라 라벤더·노랑·주황)의 꽃과 수국·수풀로 **빽빽하게**, 모서리 위쪽에 나무 수관, 풀 얼룩·풀 포기·들꽃.
- 하객은 길 위에 모이되 양옆 꽃밭 가장자리 약 56px까지 걸을 수 있다(영상도 일부가 꽃 쪽으로 걷는다). 이미지를 못 불러오면 단색 잔디로 대신 그린다(기존 동작).

## 세계·이동 상수 (`src/lib/villageSim.ts`)

- `WORLD_W=384`, `WORLD_H=512`, `HALF_W=16`, `BOX_H=64`, `AREA={x0:80, x1:304, y0:168, y1:512}`, `WALK_SPEED=48`(그대로), `ENTER_Y = WORLD_H + BOX_H`.
- 신랑·신부는 단상 위 발 위치 `(172, 136)`, `(212, 136)`, 이름표 기준 x는 190(오른쪽 맞춤)·194(왼쪽 맞춤)로 지금과 같다.
- `pickWalkerAt` 터치 여유 6px 그대로. 말풍선은 `(w.y - SPRITE_H - 8)` 위에 뜬다.

## 화면 표시 (`src/components/sections/PixelVillage.tsx`, 새 `src/lib/villageTags.ts`)

- **이름표 겹침 숨김**: 순수 함수 `layoutTags(candidates)`가 우선순위(신랑·신부 → 내 캐릭터 → 앞에 있는 하객 순)대로 사각형을 놓고, 이미 놓인 사각형과 겹치면 뺀다. 컴포넌트는 결과대로만 그린다.
- 이름표: 작은 글씨 + 흰 테두리(글씨 바깥 윤곽), 배경 상자는 없앤다. 내 캐릭터는 금색 글씨, 신랑·신부는 기존 금색·분홍. 가독성이 모자라면 반투명 상자를 허용한다(구현 단계에서 눈으로 판단).
- 말풍선: 흰 둥근 상자(`roundRect`) + 꼬리 + 은은한 그림자, 이름은 굵게, 본문은 최대 3줄. 화면 해상도로 그려 또렷하게(기존 방식).
- 그리는 순서: 발 위치(`y`) 오름차순으로 뒤→앞.
- 성능: 하객 60명 + 신랑·신부 상태에서 1프레임 그리기 시간이 눈에 띄게 늘지 않아야 한다(구현 단계에서 헤드리스로 측정해 수치를 남긴다).

## 검증

- 단위 테스트: 시트 규격(32×64, 98줄), 생성기 속성(96종 서로 다름, 9프레임 서로 다름, 투명 배경 존재, 신랑·신부 구분), 커밋된 PNG == 생성기 결과(두 PNG 모두), 배경 크기·불투명, 시뮬레이션 상수·경계, `layoutTags`(우선순위·겹침·경계).
- 시각 확인(스크립트 산출물, 저장소 밖): 캐릭터 연락표(contact sheet) 4배 확대, 하객 40명이 들어찬 화면 렌더, **참고 영상 프레임과 우리 화면을 나란히 놓은 비교 이미지**. 확인용 렌더는 작업 폴더(scratchpad)에 둔다.
- 기존 CI(tsc, eslint, vitest, `npm run build`)와 같은 PR(#43)에 이어서 올린다.

## 위험과 대응

- **그림 품질이 80%에 못 미침** → 연락표를 눈으로 보고 구현자가 반복해서 다듬는다. 마지막에 비교 이미지를 사용자에게 보여 주고 다음 단계를 정한다.
- **시트가 커짐**(288×6272) → 크기 예산 테스트, 모바일 메모리는 PNG 한 장이라 영향이 작다. 초과 시 하객 종수를 줄인다.
- **하객이 많으면 이름표가 사라져 누구인지 모름** → 의도된 동작(영상과 같음). 누르면 말풍선에 이름이 나온다.
