# 도트 마당 '2배 해상도(HD)' 설계

작성일: 2026-10-07 · 상태: 사용자 승인(시안·진행 방향) → 문서 검토 대기

## 이 문서의 위치

정원 예식장 마당의 **그림 해상도를 2배로 올리고**(세계 192×176 → **384×352**, 캐릭터 16×24 → **32×48**), 캐릭터를 코드에서 즉석으로 그리는 대신
**미리 구운 시트 PNG** 로 쓴다. 그림 원본(생성 스크립트)은 저장소에 두어 언제든 다시 만들 수 있고,
나중에 사람이 그린 시트로 바꿔 끼울 수 있다. 아래 항목은 이 문서가 대체하고, 나머지(걷기 규칙, 신랑·신부 동작, 갤러리 이동, 자동 말풍선,
글씨 선명화, 터치·말풍선·절전·접근성·에러 처리, 입장 방식)는 선행 문서를 그대로 따른다. **화면에 보이는 크기·속도·배치는 지금과 같고 세부만 2배가 된다.**

| 선행 문서 항목 | 이 문서에서 |
|---|---|
| 세계 192×176, 캐릭터 16×24 | 세계 **384×352**, 캐릭터 **32×48** (모든 좌표·속도 ×2) |
| 걷는 영역 `x∈[8,184]`, `y∈[72,176]` | `x∈[16,368]`, `y∈[144,352]` |
| 캐릭터를 글자 격자(문자열)로 정의하고 하객 id 로 색을 입혀 앱에서 굽기 | **시트 PNG** 한 장(하객 64종 + 신랑 + 신부)에서 잘라 그리기, 하객은 `hash(id) % 64` 번째 줄 |
| 배경 192×176 PNG(스크립트는 저장소 밖) | 배경 **384×352** PNG, **생성 스크립트는 저장소 안** |
| 걷기 속도 24px/s, 터치 여유 3px | 48px/s, 6px (화면에서 같은 체감) |

## 목표

참고 이미지에 더 가까운 세밀한 그림(음영·외곽선이 있는 32×48 캐릭터, 수국 화단·돌 포장길·꽃 아치가 있는 정원)으로 올리되,
앱 구조와 동작은 그대로 두고 **그림이 들어가는 곳을 PNG 두 장**(`village-bg.png`, `village-sprites.png`)으로 모은다.

## 범위

- **포함**: 384×352 정원 배경, 32×48 캐릭터 시트(하객 64종 + 신랑·신부), 두 PNG 의 생성 스크립트(순수 Node, 의존성 없음),
  세계·캐릭터 상수 2배, 시트에서 그리는 렌더링, 관련 테스트.
- **제외**: 사람이 그린 에셋 도입(나중에 같은 규격으로 교체), 새 동작 추가, 장애물·충돌, DB·API 변경, 새 npm 의존성.

## 캐릭터 시트 (`public/pic/village-sprites.png`)

- 프레임 32×48, 한 줄 = 한 사람, 열 9개: `down_idle, down_walk1, down_walk2, up_idle, up_walk1, up_walk2, side_idle, side_walk1, side_walk2`
  (`side` 는 오른쪽을 보는 모습, 왼쪽은 그릴 때 좌우 반전). 시트 크기 `288 × (48 × 66)` = 288×3168, 배경은 투명.
- 줄 0~63 = 하객 64종, 줄 64 = 신랑, 줄 65 = 신부.
- 하객 64종은 시드 고정으로 만든다: 머리 모양 6종(짧은·단발·긴·포니테일·올림·곱슬), 옷 5종(티셔츠·긴팔·원피스·후드·정장은 신랑 전용),
  피부 5종, 머리색 8종, 옷·바지·신발 색, 모자(없음·캡·머리 꽃·리본)를 조합하되, 머리 모양·옷·피부색이 골고루 나오게 한다(각 머리 모양 8종 이상).
  하객에게는 정장을 쓰지 않는다.
- 신랑: 짧은 머리, 검은 정장 `#2f3340`, 흰 셔츠, 빨간 타이, 바지 `#1e1f26`. 신부: 긴 머리, 흰 드레스 `#f6f3ee`, 머리 꽃. (모양은 시안과 같다.)
- 그림 방식(시안과 같다): 도형 → 위·왼쪽은 밝게, 아래·오른쪽은 어둡게 음영 → 실루엣 바깥 1px 외곽선. 걷기는 앞·뒤에서는 한쪽 다리를 2px 들고 팔을 반대로 흔들며,
  옆에서는 다리를 ±3px 벌리고 팔을 반대로 흔든다. 지금처럼 걷기 애니메이션은 `walk1 → idle → walk2 → idle` 을 초당 6프레임으로 돈다.

## 배경 (`public/pic/village-bg.png`)

- 384×352 PNG. 시안과 같은 구성: 모서리의 큰 버드나무 수관, 가운데 위의 마룻바닥 단상과 계단 3단, 꽃 아치·흰 커튼, 단상 양옆의 나무 화단(수국처럼 빽빽한 꽃),
  단상에서 아래로 이어지는 돌 포장길(`x ∈ [168, 215]`)과 양옆 꽃 덤불, 라벤더와 오른쪽 꽃덤불, 잔디 얼룩·풀 포기·들꽃.
- 걷는 영역 `x∈[16,368]`, `y∈[144,352]`(발 위치). 위쪽(단상·화단·나무)은 장식이고 충돌은 없다. 이미지를 못 불러오면 단색 잔디 배경으로 대신 그린다.

## 그림 생성 스크립트 (저장소 안, `scripts/village-art/`)

- 순수 Node(ESM, 외부 의존성 없음): 캐릭터 생성기, 배경 그리기, PNG 인코더(`zlib` 내장), 두 PNG 를 쓰는 진입점(`npm run village:art`).
- 시드가 같으면 항상 같은 그림이 나온다(난수는 mulberry32). 그림 로직과 PNG 인코딩은 분리한다.
- 앱 코드는 이 스크립트를 import 하지 않는다(런타임에는 PNG 만 쓴다). 사람이 그린 시트로 바꿀 때는 PNG 두 장만 교체하면 되고 스크립트는 지워도 된다.

## 렌더링 규칙

- 도트 세계는 지금처럼 `imageSmoothingEnabled = false` 로 그린다. 캔버스 배율은 `max(1, ceil(css폭 × dpr / 384))`.
- 384px 그림을 폭 336css px 로 보이면 1도트가 0.875css px 라 브라우저가 약간 줄여서 보여 준다. 줄이는 방식은 부드러운 보간(`image-rendering: auto`)을 쓴다 —
  `pixelated` 는 줄일 때 도트가 불규칙하게 빠져 들쭉날쭉해지기 때문이다. 글씨는 화면 해상도로 그리는 지금 방식을 유지한다.
- 시트에서 `drawImage(sheet, col×32, row×48, 32, 48, dx, dy, 32, 48)` 로 잘라 그린다. 왼쪽은 좌우 반전. 하객마다 캔버스를 따로 굽지 않는다(메모리·시간 절약).
- 시트를 못 불러오면(`onerror`) `마을을 불러오지 못했어요` 를 보여 준다. 배경만 못 불러오면 단색 잔디로 대신하고 캐릭터는 그대로 그린다.

## 테스트

- 시트 규격: PNG 288×3168, 400KB 미만. 배경: 384×352, 200KB 미만.
- 생성기: 하객 64종이 서로 다르게 나오고(예: 64줄 중 같은 모양 쌍이 거의 없음), 모든 프레임에 불투명 픽셀이 있으며, 앞·뒤·옆과 걷기 프레임이 서로 다르고,
  신랑·신부가 하객 줄과 다르며, 같은 시드는 같은 결과를 낸다. PNG 인코더는 인코딩한 바이트를 `zlib` 로 풀어 원래 픽셀과 같은지 확인한다.
- 이동·시트 규격 상수: `villageSim` 의 영역·속도·반폭, `pixelSprite` 의 `lookRowFromId` 가 같은 id 에 항상 같은 줄(0~63)을 주는지, `frameRect` 가 열·줄 좌표를 맞게 계산하는지.
- 화면(샘플 데이터 임시 페이지, 저장소에 넣지 않음): 선행 계획의 10가지 검증 + 시트 규격 때문에 늘어나는 항목(캐릭터 64종이 다양하게 보임, 왼쪽 반전, 배경·시트 로드 실패 폴백).
  실제 방명록 탭과 `#gallery` 는 배포 미리보기에서 확인한다.

## 한계(알고 가는 것)

- 코드로 그린 그림이라 참고 이미지보다 소박하다. 에셋을 구하면 PNG 두 장을 같은 규격으로 교체한다.
- 하객이 64종이라 100명이면 같은 모습이 겹칠 수 있다(이름표는 다르다).
- 시트·배경 PNG 용량이 늘어난다(배경 약 80KB, 시트 약 100~300KB 예상). 첫 로드에 둘 다 받는다.
- 384px 그림을 줄여 보이므로 지금의 "굵은 도트" 느낌보다 세밀하고 약간 부드럽다.
