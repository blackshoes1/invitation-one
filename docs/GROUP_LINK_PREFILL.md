# 그룹 링크에서 이름 채우기 — 명단에서 고르게 한다

작성: 2026-09-09 · 예식 2026-10-18

## 문제

`/delivery/group/<슬러그>` 는 단톡방에 뿌리는 **한 개의 주소를 여러 명이 같이
쓰는** 링크다. 그래서 서버는 지금 누가 눌렀는지 알 수 없다. 개인 초대 링크
(`?i=<토큰>`)만이 사람을 특정하고, 그때만 이름·연락처가 자동으로 채워진다.

"그룹 링크로 들어와도 개인 정보가 채워지게" 는 곧 **누구인지 알아내는 수단을
하나 더 만드는 일**이다. 그래서 어디까지 할지가 설계의 전부다.

## 고른 것 — 명단에서 본인을 고르면 이름·연락처가 채워진다

명단에 있는 **이름 목록만** 내려주고 하객이 자기 이름을 고른다. 연락처는
**제출 시점에 서버가** 명단에서 붙인다 (`rosterPhone`).

| | 개인 초대 링크 `?i=` | 그룹 링크 + 명단 고르기 |
|---|---|---|
| 이름 | 자동 | 골라서 채움 |
| 연락처 | 자동 (서버가 **토큰**으로 채움) | 자동 (서버가 **고른 이름**으로 채움) |
| 브라우저로 내려가는 번호 | 마스킹본 (본인 확인용) | **없음 — 한 자리도** |
| 신원 | 토큰으로 증명됨 | **증명 아님** |
| 명단 연결(`group_members`) | 됨 | **안 됨** |

## 핵심은 "번호를 브라우저로 안 보낸다"이다

초대 링크는 토큰이 신원을 증명하므로 마스킹 번호(`010-****-1234`)를 보여줘도
**본인에게** 보여주는 것이다. 그룹 링크는 누가 눌렀는지 알 수 없으므로 마스킹본
조차 보여주면 링크를 가진 누구나 남의 뒷자리를 알아낼 수 있다. 그래서 화면에는
"명단에 있는 OO님 번호로 보낼게요" 만 뜨고, 실제 번호는 서버에서만 붙는다.

이렇게 두면 **새로 새는 정보가 없다.** 남는 것은 "링크를 가진 사람이 남의 이름으로
신청할 수 있다"인데, 그건 **지금도 가능하다** — 이름을 치고 아무 번호나 넣으면
된다. 달라지는 건 그 신청에 그 사람의 진짜 번호가 붙는다는 것뿐이고, 오히려
신랑신부가 전화 한 통으로 확인할 수 있게 된다.

## 고르지 않은 것 — 이름 + 번호 뒤 4자리

이쪽은 다르다. 뒷자리를 맞히게 하면 **맞는지 틀리는지가 응답으로 새어** 링크를
가진 사람이 1만 가지를 넣어보며 남의 번호를 알아낼 수 있다(조회 오라클). 같은
이유로 '내 신청 찾기'가 관리 토큰을 너무 쉽게 내주던 것을 **막았다**
(`consume_recovery_token`). 그걸 막아 놓고 여기서 다시 여는 것은 앞뒤가 안 맞다.

## 넘지 않는 선

이름을 골랐다는 사실은 **신원 증명이 아니다.** 그러므로 그 사실로

- 번호를 **화면에 보여주지** 않는다 (마스킹본 포함). 서버에서만 붙인다
- 초대 토큰을 발급하지 않는다
- `group_members` 에 참여자를 연결하지 않는다 — 명단의 "이 사람이 신청했다"는
  상태는 토큰으로 증명된 것만 반영해야 한다

이 선을 넘는 순간 명단이 조회 API 가 된다.

## 누구 번호인지 확실할 때만 붙인다

`rosterPhone` 이 번호를 돌려주지 **않는** 경우 — 그때는 하객이 직접 입력한다:

- 그 이름이 명단에 없다
- **동명이인** — 아무거나 붙이면 엉뚱한 사람에게 배송 연락이 간다
- 명단에 번호가 없거나 형식이 깨져 있다

이름 목록 API 의 `hasPhone` 도 **같은 규칙**이라 화면과 제출이 어긋나지 않는다.
그리고 하객이 이름을 손으로 고치면 명단 번호를 즉시 버린다 — 고른 이름과 다른
이름이 되는 순간 "누구 번호인지"의 보장이 깨지기 때문이다.

## 고를 기회는 **페이지를 열자마자** 와야 한다

처음에는 이걸 이름 입력칸 옆의 작은 밑줄 링크로만 뒀다. 메뉴를 누르고 폼에
들어가야 나오는 자리라 **있는 줄도 모르고 지나쳤다**(2026-09-09, 실제로 겪음).
기능이 있어도 닿지 않으면 없는 것과 같다.

그래서 주 경로는 그룹 페이지 **첫 화면의 카드**(`RosterIntroCard`)다. 거기서 한
번 고르면 아래 신청서 넷(직접배달·합류·제안 수락·마음배송)에 이름이 채워진 채로
들어간다. 입력칸 옆 작은 링크(`RosterPicker`)는 그걸 지나쳤거나 다른 이름으로
바꾸려는 사람을 위한 보조로 남긴다.

개인 초대 링크(`?i=`)로 들어온 사람에게는 카드를 띄우지 않는다 — 서버가 이미
누군지 알기 때문에 고를 이유가 없다.

## 구현

- `GET /api/delivery/group/roster?slug=` — **이름과 `hasPhone` 만** 반환.
  `phone` 은 라우트 안에서만 보고 응답에는 boolean 으로만 나간다.
  `member_id`·`invited_at` 은 조회조차 하지 않는다.
  - `group_members` 는 anon 이 못 읽는다(20260731000200 에서 권한 회수). 그래서
    RPC 가 아니라 service_role 을 쓰는 Next 라우트에서만 읽고 걸러 내보낸다.
  - 없는 슬러그도 **빈 목록**으로 답한다 — 슬러그를 넣어보며 그룹의 존재 여부를
    캐는 데 쓰이지 않게.
  - IP 당 10분에 60회 제한 · `Cache-Control: no-store, private` · 동명이인은 합침.
- `rosterPhone(groupId, name)` (`src/lib/deliveryApi.ts`) — 제출 3경로
  (`create` · `join` · `group/accept`)가 `rosterName: true` 를 받았을 때만
  부른다. 여기서 나온 번호는 RPC 의 `p_phone` 으로만 들어가고 응답에는 없다.
- `useRoster` / `RosterNameList` — 목록 조회와 표시. **누르기 전에는 불러오지
  않는다.** 안 고르는 사람에게까지 명단을 내려보낼 이유가 없다.
- `RosterIntroCard` — 그룹 페이지 첫 화면 카드(주 경로). 고른 이름은 페이지
  상태(`pickedName: PickedName`)로 들고 있다가 신청서 넷의 `picked` 로 내려간다.
  명단이 비어 있다고 확인되면 카드를 접는다.
- `RosterPhoneBox` — 번호 입력칸 자리에 "명단에 있는 OO님 번호로 보낼게요" 와
  "다른 번호 입력" 만 띄운다. `InvitePhoneBox` 와 달리 **숫자를 안 보여준다.**
- `RosterPicker` — 이름 입력칸 옆 작은 링크(보조). 같은 네 곳에 붙는다
  (직접배달 1단계 · 합류 · 제안 수락 · 마음배송). 그룹 슬러그가 없으면
  (개인 주문 `/delivery`) 둘 다 아예 그리지 않는다.
- `picked` 는 **`invite` 와 별개의 prop** 이다. 초대 프리필에 섞으면 "토큰으로
  확인된 신원"과 "본인이 고른 이름"이 한 값이 되어, 마스킹 번호 표시·명단 연결
  같은 초대 전용 동작이 딸려온다.
- 마음배송(`HeartForm`)은 이름만 채운다 — 연락처가 선택 입력이라 굳이 명단
  번호를 끌어올 이유가 없다.

## 남는 노출

명단의 **이름**은 그룹 링크를 가진 사람 누구에게나 보인다. 같은 모임 사람들은
어차피 서로 아는 사이라 잃는 게 크지 않다고 보고 택했지만, **링크가 모임 밖으로
전달되면 이름도 같이 나간다.** 이게 싫은 그룹이 생기면 그룹별로 끄는 스위치를
붙이는 게 다음 수순이다 (지금은 그런 요구가 없어 만들지 않았다).

### 한 번 멈췄다가 다시 넣었다 (2026-09-09)

바로 이 노출 때문에 신랑신부가 작업을 한 번 멈췄다. 검토한 대안은 셋이었다:

1. **명단을 안 보여주고** 이름을 직접 치게 한 뒤 서버가 본인 것만 확인
2. **그룹별 on/off 스위치** (`groups` 에 컬럼 추가 — 마이그레이션 필요)
3. **명단 고르기 제거**

결국 ①·② 없이 원래 설계 그대로 다시 넣기로 했다. ①은 "그 이름이 명단에 있느냐"
가 응답으로 새어 결국 명단을 한 번에 못 볼 뿐 캐낼 수는 있게 되고, 화면상 이득도
거의 없다. ②는 언제든 위에 얹을 수 있어(컬럼 하나 + 라우트에서 빈 목록 반환)
지금 미리 만들 이유가 없다.

**번호는 여전히 한 자리도 안 내려간다** — 멈추기 전과 같다. 바뀐 판단은
"이름이 모임 밖으로 나갈 수 있다"를 감수한다는 것 하나뿐이다.

## 더 나은 길이 이미 있다

관리자 화면의 **`전체 개인 링크 복사`** 는 명단 전체를 `이름: 링크` 형태로 한 번에
복사해 준다. 그 덩어리를 단톡방에 붙여넣으면 각자 자기 이름 줄을 누르고, 그때는
이름과 연락처가 **둘 다** 자동으로 채워진다. 명단 고르기는 그 링크를 못 받았거나
잃어버린 사람을 위한 차선책이다.
