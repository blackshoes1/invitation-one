# 그룹 멤버 초대 링크 운영

## 관리자 사용법

- 멤버 이름과 연락처를 등록합니다. 연락처를 수정한 뒤 `연락처 저장`을 누르거나 링크 버튼을 누르면 저장 완료 후 링크를 준비합니다. 저장 실패 시 링크 발급은 중단됩니다.
- `개인 신청 링크`: 본인을 자동 인식하고 소속 모임 정보를 보여주며, 주문은 개인 주문입니다.
- `그룹 합류 링크`: 본인을 자동 인식하고 그룹 주문 현황·일정 합류 화면으로 들어갑니다.
- 전체 복사는 `이름: 링크` 목록을 만듭니다. 각 사람에게 해당 주소만 1:1로 보내세요. 연락처가 없거나 기존 주소를 복원할 수 없는 멤버는 제외 목록에 이유를 표시합니다.
- 클립보드 접근이 실패해도 결과란에서 직접 주소를 선택해 복사할 수 있습니다.
- `링크 재발급`은 별도 확인 후 해당 멤버의 개인 신청·그룹 합류 주소를 함께 교체합니다. 이전 주소는 무효가 됩니다.

## 기존 링크 호환과 재복사

스키마 변경은 없습니다. 기존 `invite_token_hash`, `invited_at` 컬럼을 사용합니다.

새로 발급하는 토큰은 서버 전용 서명 키, 멤버 ID, 정규화한 발급 시각으로 HMAC-SHA256을 계산한 128비트 값입니다. 용도 문자열을 별도로 포함하며, 기존 32자리 hex 형식과 SHA-256 조회 규약을 유지합니다. DB에는 계속 해시만 보관합니다. 복사 요청은 재생성한 토큰의 해시가 현재 저장값과 일치할 때만 주소를 반환하며, 발급 시각이나 해시를 바꾸지 않습니다.

이전 방식의 무작위 토큰은 해시에서 원문을 복원할 수 없습니다. 기존 링크는 계속 유효하고, 복사 요청·전체 복사가 이를 자동으로 교체하지 않습니다. 이미 보낸 메시지에서 주소를 복사하거나, 새 주소가 필요할 때 해당 멤버의 `링크 재발급`을 사용하세요.

서명 키는 기존 `signingKeyFromEnv` 규칙을 사용합니다. `APP_SIGNING_SECRET`이 우선이며, 없으면 서버용 `SUPABASE_SERVICE_ROLE_KEY`와 `ADMIN_PASSWORD`로 파생합니다. 키를 변경하면 이전 키로 발급한 주소를 다시 복원할 수 없지만, 이미 받은 주소의 해시 조회는 계속 작동합니다. 안정적인 재복사가 필요하면 `APP_SIGNING_SECRET`을 유지하세요. 공개 환경변수는 키 재료로 사용하지 않습니다.

새 발급·재발급은 조회한 기존 해시와 연락처가 바뀌지 않았을 때만 저장합니다. 동시 요청이나 저장 실패 시 저장되지 않은 주소를 반환하지 않으며, 다시 복사를 시도하면 됩니다. 전체 작업 중 일부 실패는 대상별로 표시합니다.

## 수신자 화면

초대 이름·마스킹 연락처를 표시합니다. `본인이 아닌가요? 내 정보로 새로 시작`은 초대 토큰과 주문 전환 토큰을 주소에서 제거하고 페이지를 새로 열어 기존 폼·모임 응답 상태를 비웁니다. 본인 링크를 다시 받으면 자동 입력을 이용할 수 있습니다. 링크를 확인하지 못하면 재시도와 본인 링크 요청을 우선 안내합니다.

이 링크는 본인 인증 수단이 아니라 소지자에게 신청·응답 권한을 주는 주소입니다. 다른 사람에게 전달하면 원래 수신자로 인식됩니다.

## 검증 범위

`tests/unit/groupInviteApi.test.ts`는 발급·재복사·명시적 재발급, 옛 링크 유지, 일괄 제외 결과, 관리자 권한, 서명 키 누락, 동시 변경·DB 실패 처리를 검증합니다. DB 호출은 모의 객체를 사용합니다.

`tests/e2e/group-invites.spec.ts`는 관리자 저장→복사 순서, 저장 실패 차단, 새로고침 후 복사, 재발급 분리, 일괄 복사·클립보드 실패, 잘못 받은 링크의 신원 초기화, 무효 링크 안내를 검사합니다. API는 테스트 응답으로 대체하므로 운영 DB·SMS·카카오에 접근하지 않습니다.
# 추가 보완: 입력 초기화와 신청·명단 연결

- 작업 프롬프트: `docs/INVITE_RELIABILITY_PROMPT.md`.
- ‘내 정보로 새로 시작’은 임시 날짜·시간·기사·메시지도 삭제한다. 초안은 개인 초대·전환·신청 경로의 SHA-256 범위값과 함께 저장하며 원본 토큰과 연락처는 저장하지 않는다. 같은 범위의 새로고침만 복원한다. 소유 범위 없는 이전 초안은 폐기한다.
- 마음배송은 초대 토큰을 서버에 전달한다. 서버/DB에서 신원을 다시 확인하고 명단 이름·기존 연락처로 저장한다. 다른 연락처를 입력하면 그 번호를 사용하되 명단 연결은 유지한다. 익명·비공개 설정은 그대로 적용한다.
- 개인 배송·합류·제안 수락·마음배송의 구성원 연결은 DB 트랜잭션 안에서 처리한다. 연결 실패 시 신청과 알림 예약도 롤백하며, 기존에 다른 구성원과 연결된 마음배송을 다른 초대로 전환하지 못한다.

## 배포 순서

1. `20260909060754_atomic_invite_submission.sql`을 DB에 **먼저** 적용한다. 기존 배송 RPC 시그니처와 마음배송 v2를 유지하므로 현재 앱과 호환된다. 새 테이블/공개 권한 추가는 없다.
2. DB 검증과 CI 통과 후 앱을 배포한다. 새 마음배송 API는 `send_heart_v3`를 요구한다. 마이그레이션 누락 시 성공으로 위장하거나 v2로 되돌리지 않고 실패한다.
3. 운영에서 개인 링크→마음배송→관리자 명단 반영을 확인한다. 운영 확인은 모의/테스트 DB 검증과 별도로 기록한다.
4. 앱 롤백 시 DB 함수는 유지해도 된다. 기존 앱의 배송 후 추가 연결 쓰기는 동일 값이라 호환된다.

DB 검증: `bash scripts/db-verify.sh`가 `supabase/tests/atomic_invite_submission_test.sql`도 실행한다. 네 신청 경로의 연결 실패 강제 주입, 전체 롤백, 정상 재시도, 다른 초대로의 전환 거부, 연락처 대체, 공개 설정과 실행 권한을 검사한다. **새 테스트 DB 전용이며 운영 DB에서 실행하지 않는다.**
