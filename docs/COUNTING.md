# 집계 정의 — 무엇을 세고 있는가

작성: 2026-09-07 · 예식 2026-10-18

관리자 화면의 숫자들은 **세는 대상이 서로 다르다.** 예전에는 그룹 카드의 "신청 n명"
하나에 직접배달과 마음배송이 섞여 있었고, 명단 배지는 취소·마음배송까지 "신청함"으로
표시해서 카드와 배지가 서로 다른 뜻을 갖고 있었다. 이 문서가 기준이다.

## 네 가지를 구분한다

| 이름 | 뜻 | 단위 | 어디서 |
|---|---|---|---|
| **명단 인원** | 관리자가 등록한 `group_members` 행 수 | 사람 | `roster_count` |
| **직접배달 신청** | 취소되지 않은 `직접배달` participants 행 수 | 기록 | `order_count` |
| **마음배송** | `마음배송` participants 행 수 | 기록 | `heart_count` |
| **신청 기록 수** | 위 둘의 합 | 기록 | `member_count` · `totals.records` |

**신청 기록 수는 고유 인원이 아니다.** 같은 사람이 마음배송을 보낸 뒤 직접배달을
신청하면 2건으로 잡힌다. 그래서 UI 는 명단만 "명", 신청은 "건"으로 쓴다.

**신청 기록 수는 식수(결혼식 참석 인원)도 아니다.** 청첩장을 받는 것과 예식에 오는
것은 별개다. 식수는 이 화면에서 계산하지 않는다.

### 고유 신청자 수는 내려주지 않는다

이름만으로 중복을 제거하면 동명이인이 한 사람으로 합쳐진다. 명단 연결
(`participants.group_member_id`)이 있는 기록만 사람 단위로 묶을 수 있는데, 연결이
없는 과거 신청이 남아 있어 전체에 대한 정확한 고유 인원은 계산되지 않는다.
**계산할 수 없는 숫자를 만들어 보여주는 대신 내보내지 않는다.**

## 포함·제외 규칙

- **취소**(`deliveries.status = '취소'`) 된 직접배달은 **제외**한다. 취소 이력만 남은
  사람은 신청자가 아니며, 새 주문에 다시 등록할 수 있어야 한다.
- **완료** 주문은 **포함**한다 (기존 기준 유지).
- **숨김**(`deliveries.hidden`)은 **표시용 속성**이라 취소와 같이 취급하지 않는다.
  주문 목록에서 안 보일 뿐 그 사람은 여전히 온다.
- **마음배송**은 주문(`deliveries`)이 없으므로 취소 개념이 없다. 전부 센다.

## 그룹 귀속

- 그룹 집계는 `participants.group_id` 기준이다.
- **개인 링크로 신청한 명단 구성원은 `group_id` 가 비어 있다** → 그 그룹의
  `order_count` 에 **합산하지 않는다.** 대신 명단 행에 `personal` 배지로 드러난다
  (`participants.group_member_id` 로 찾는다). 그룹 주문이 아닌 것을 그룹 실적에
  합치면 그룹 카드가 실제보다 커진다.
- `totals` 는 그룹에 묶이지 않은 신청까지 포함한 전체다. 그룹별 합보다 크면 그 차이가
  "그룹 외"다.

## 명단 배지

카드 집계와 **같은 기준**을 쓴다.

| 배지 | 조건 |
|---|---|
| `신청` | 이 사람의 취소되지 않은 직접배달이 있고, 그 주문이 그룹 주문 |
| `신청(개인)` | 위와 같으나 개인 링크로 신청해 그룹에 묶이지 않음 |
| `마음` | 마음배송 기록이 있음 — 직접배달 신청과 **별개로** 표시 |

마음배송만 한 사람에게 `신청` 을 붙이면 관리자가 그 사람 몫의 청첩장을 준비하지
않게 된다. 그래서 배지를 합치지 않는다.

## 실패는 0 이 아니다

집계 조회가 실패하면 **숫자를 그리지 않는다.** 0 으로 표시하면 "아무도 신청 안 함"과
구분되지 않는다. API 는 500 을 돌려주고 화면은 경고를 띄운다.
