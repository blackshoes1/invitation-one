# 관리자 주문 개인 추가 및 코드 검토

검토 기준: main b53b97a (2026-09-14 확인). 관리자 주문·그룹 명단·참여자 연결 중심의 검토이며 전체 보안 감사는 아니다.

## 구현

관리자 → 주문 → 진행 중인 주문 카드 → **명단에서 추가** → 이름/연락처 검색 → 개인 추가.
그룹 주문은 해당 그룹 명단, 그룹 없는 주문은 그룹을 선택해 개인을 추가한다. 기존 주문의 그룹과 대표자는 유지한다.
연락처가 없는 명단도 추가할 수 있다. 이름·연락처는 클라이언트 입력 대신 DB 명단에서 가져온다.
이미 다른 유효 주문에 있는 개인, 그룹 불일치, 취소/완료 주문은 차단한다. 같은 주문 재시도는 성공으로 처리하되 중복 삽입하지 않는다.
취소된 주문 및 마음배송 이력은 추가를 막지 않는다. 신원이 불명확한 기존 동명 참여자는 자동 연결하지 않고 확인 오류를 표시한다.
참여자 등록과 알림 outbox 제외를 하나의 트랜잭션으로 수행한다. 문자는 보내지 않는다.

## 적용

`supabase/migrations/20260914045031_admin_add_order_member.sql`을 대상 DB에 먼저 적용한 후 앱을 배포한다.
기존 행/테이블은 변경하지 않으며 service_role만 새 함수를 실행할 수 있다.
이번 작업에서 운영 DB 적용, 실제 알림 발송, 운영 배포는 수행하지 않았다.

## 검증

- Vitest: 32개 파일, 240개 테스트 통과.
- TypeScript, 변경 파일 ESLint, Next.js 프로덕션 빌드 통과.
- PGlite의 격리된 최소 스키마에서 SQL 직접 실행: 추가, 재시도, 다른 주문 중복, 상태/그룹/신원 충돌, 취소/마음배송 이력, 개인 주문, 알림 제외, 역할별 함수 권한 검증.
- DB 회귀 스크립트: `tests/db/admin-add-order-member.mjs`. 별도 임시 폴더에 `@electric-sql/pglite`를 설치하고 `PGLITE_MODULE=/절대경로/node_modules/@electric-sql/pglite/dist/index.js node tests/db/admin-add-order-member.mjs`로 실행.
- 브라우저 실행 미완료: Chromium이 설치되어 있지 않고 다운로드가 네트워크 시간 초과로 실패했다. 아래 회귀 테스트는 작성했으나 실행 통과를 확인하지 못했다.
- 브라우저 회귀 테스트: `tests/e2e/admin-add-order-member.spec.ts`. 관리자 API 모의 응답으로 검색, 추가, 인원 갱신, 중복/완료 주문 버튼 차단을 검증하도록 작성.
- 운영 Supabase 전체 스키마 통합 및 서로 다른 등록 경로의 동시 요청은 검증하지 않았다.
