# 개인 초대 링크 안정성 보완 프롬프트

저장소: https://github.com/blackshoes1/invitation-one
작업 대상: PR #15의 개인별 초대 링크 개선 사항을 유지하면서 아래 문제를 수정한다.

## 목표와 원칙

- 개인별 링크의 초대 토큰으로 사람을 식별하고, 소속 그룹이 있으면 그룹 정보를 표시한다.
- 공용 그룹 주소나 이름·전화번호 추측으로 특정인을 자동 식별하지 않는다.
- 개인 신청과 그룹 합류의 기존 주문 구분을 유지한다.
- 기존 링크 재복사·명시적 재발급·전화번호 저장 동작을 유지한다.
- 저장소 AGENTS.md와 설치된 Next.js 문서를 확인하고 기존 변경 사항을 보존한다.

## 구현할 사항

1. **다른 사람으로 새로 시작할 때 임시 입력 초기화**
   - ‘본인이 아닌가요? 내 정보로 새로 시작’에서 초대·전환 토큰과 임시 저장한 날짜, 시간, 기사, 메시지를 초기화한다.
   - 같은 탭에서 다른 사람의 링크나 다른 신청 경로를 열어도 이전 사람의 초안이 복원되지 않도록 초안 소유 범위를 구분한다.
   - 같은 사람·같은 신청 경로의 새로고침에서는 입력 복원을 유지한다.

2. **마음배송에도 개인 식별 유지**
   - 개인 초대 토큰을 마음배송 API까지 전달하고 서버에서 유효성을 확인한다.
   - 저장할 이름과 명단 연결은 서버가 확인한 초대 신원을 기준으로 결정한다.
   - 연락처를 다시 입력하지 않아도 기존 초대 연락처를 사용할 수 있도록 한다. 직접 입력한 연락처가 있다면 형식을 검증한다.
   - 만료·재발급된 링크나 다른 그룹으로의 잘못된 연결을 거부한다.
   - 초대 없이 작성하는 기존 마음배송과 익명 공개 설정을 유지한다.

3. **신청 저장과 그룹 구성원 연결의 원자성 보장**
   - 개인 배송, 그룹 합류, 그룹 대표 수락, 마음배송에서 신청과 participants.group_member_id 연결을 동일 DB 트랜잭션으로 처리한다.
   - 연결 실패를 로그만 남기고 성공으로 응답하는 처리를 제거한다.
   - 실패 후 재시도로 중복 신청이 발생하지 않도록 연결 실패 시 전체 저장을 롤백한다.
   - 클라이언트가 보낸 구성원 ID를 그대로 신뢰하지 않고 초대 토큰을 검증한다.
   - 필요한 DB 마이그레이션과 적용 순서를 문서화한다. 운영 DB 변경은 접근 권한과 대상이 확인된 경로에서만 수행한다.

4. **회귀 검증과 CI 수정**
   - 전화번호가 안내와 확인 영역에 각각 나타나는 기존 E2E 테스트를 의미 있는 영역으로 한정한다. 중복 표시는 숨기지 않는다.
   - 새로 시작 후 초안 삭제, 다른 사람 간 초안 분리, 마음배송 토큰 전달·거부·명단 연결을 검증한다.
   - DB에서 연결 실패 시 전체 롤백, 유효 초대의 연결 성공, 일반 신청 호환성을 검증한다.
   - lint, TypeScript, 단위 테스트, 빌드와 관련 E2E/DB 검사를 실행한다.

## 완료 조건 및 전달

- 수정 내용, 검증 결과, 남은 제약을 기록하고 기존 PR #15를 업데이트한다.
- 프롬프트 파일 다운로드 링크와 PR 링크를 제공한다.
- 배포 권한이 확보되었고 필수 검증이 통과했을 때 기존 배포 요청을 이어서 수행한다.
- 앞서 확인된 Vercel 403을 다른 인증 경로로 우회하지 않는다. 배포가 막히면 수정과 검증을 완료한 결과 및 구체적인 차단 원인을 보고한다.
